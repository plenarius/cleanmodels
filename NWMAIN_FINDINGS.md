# nwmain-linux static-analysis findings (running list)

Static analysis only, from `nwmain-linux` (unstripped x86-64, Steam NWN:EE, 2026-10-11).
Addresses are nm/file vaddrs. Ghidra shows them +0x100000 (PIE load base).
Decompiles, the Ghidra project and the scripts live in `~/dev/nwn/nwmain-analysis/` (see its README).
Status: CONFIRMED (read in code), UNVERIFIED (inferred or incomplete). Decision column is ours to fill in.

## Pipeline

`MdlNodeTriMesh::InternalPostProcess` (0x4577c0), when the node has no GPU vertices yet, runs:
`ProcessVerts` -> `InternalGenVertices` (virtual, vertex dedup + degenerate strip) -> `BuildNeighborLists`
-> `BuildVertexIndices` -> `GenerateVertexData` -> `CalculateTangentSpaceBasis`.
If GPU vertices already exist (binary load), only `CalculateTangentSpaceBasis` runs.
AnimMesh, DanglyMesh and Skin have their own variants of the same chain.

## Findings

| 1 | Vertex dedup | CORRECTED. `InternalGenVertices` exists per node type. TriMesh (0x454610), AnimMesh, DanglyMesh and Skin do a plain GLOBAL dedup: build a `NodeVertex` per face corner, scan the whole vertex list in order, take the first `operator==` match, else append. Only the AABB variant (0x454920) uses the edge-adjacency scheme (scan earlier faces, need >=2 equal corners). `BuildVertexIndices` does no dedup. | CONFIRMED (asm read for TriMesh and AABB; Anim/Dangly/Skin seen via call targets only) | Our global hash matches the TriMesh scheme. The AABB scheme is irrelevant to us (we don't strip or re-dedup walkmeshes). | DONE: AABB variant ported (`expandOpts.aabbMerge`); `wok` and `meshtdc5076` now match exactly |
| 2 | Dedup key | `NodeVertex::operator==` (0x45a300): per-face byte (`mirrorlist`), position, normal (float `==`, so -0 == +0), UV0-3, color and tangent+w only if present. Material and smoothing group are NOT in the key. Subclasses extend it: `NodeVertexAnim::operator==` (0x45a550), `NodeVertexDangly::operator==` (0x45a8d0), and the Skin path also calls `SkinVertexWeight::operator==` (0x43d270). | CONFIRMED | Our `vertKey` adds mat and sg (only causes extra splits) and has no skin weight, dangly constraint or anim data. | see finding 16 |
| 3 | `mirrorlist` | Optional ASCII mesh field `mirrorlist` (parsed as `List<int>` in `InternalParseField`, 0x44ced0). One int per face; the low byte goes into the `NodeVertex` key, so faces with different values never share a vertex. If the field is absent the value stays 0 for every face. No local model or hak contains the field, and cleanmodels has no handling for it. It is not stored in binaries. | CONFIRMED | We ignore it. Zero impact on current assets. Only matters for a model that authors it (we would over-merge). | DONE: parsed, written, and in the merge key (`MeshData.MirrorList`) |
| 4 | `BuildVertexIndices` | No dedup. Copies each face's three u16 indices (face +0x1a/+0x1c/+0x1e) into one flat index buffer. | CONFIRMED | OK | none |
| 5 | Degenerate faces | After the global dedup, walks faces backward and deletes any with two equal GPU indices (face +0x1a/+0x1c/+0x1e). In a generic mesh that means two corners that compare equal under `NodeVertex::operator==`. Fixture proof: `tdc01_g02_03` / `tdc01_g02_01` node `object01`, faces `18 0 9`, `19 0 18`, `20 0 19` are removed (19 -> 16); verts 9, 18, 19, 20 share coordinates. | CONFIRMED | DONE (uncommitted): `buildExpandedMeshOpts(mesh, true)` strips them for non-AABB meshes. We now emit 16 faces for `object01`, same as the game. Vertices the stripped faces introduced are kept, as in the game. | DONE |
| 6 | Degenerate strip vs AABB tree | The same delete loop runs for AABB nodes, but they use the adjacency dedup and no fixture has an AABB node whose face count changed. How the game keeps tree indices valid after a delete is not observed. | UNVERIFIED (no test data) | We deliberately do not strip AABB nodes. | wait for data |
| 7 | AABB tree | `Parse(char const*, AABB*&)` (0x446ed0) reads `"%f %f %f %f %f %f %d %d"` per node. Fixture proof: the game's tree equals the authored tree entry-for-entry in all 20 AABB nodes across both fixture sets (3 to 399 nodes each), including odd ordering. | CONFIRMED | "Split order differs" only applies to our `RebuildAABB`. Fix the doc. | DONE: COMPILE.md fixed |
| 8 | Normal generation | `ProcessVerts` (0x454dd0), only when the mesh has no normals. Per corner: for earlier faces sharing the vertex and a smoothing bit, reuse its stored normal if dot(face normal, that normal) >= -0.99 (double at 0x13f0548). Otherwise accumulate area-weighted cross products of LATER faces only. If the sum is exactly zero, use the normalised face normal, else normalise the sum. | CONFIRMED | `generateNormals` sums all overlapping faces and falls back to (0,0,1) when the sum is ~0. Back-to-back same-SG faces (leaves, planes) get +Z normals. | DONE (uncommitted): `generateNormals` is now a port of `ProcessVerts`. Oracle vertex parity improved: `head_g`, `line566`, `line1073`, `line1961`, `line1962` now match the game exactly (baseline entries removed); `box155793` -2 -> -4. Also made the dedup key treat -0 as +0 (game uses float ==). |
| 9 | Tangent algorithm | `CalculateTangentSpaceBasis` (0x457710) gates then calls `FUN_00556190` (file 0x456190). Per triangle: t = ((v2-v0)(p1-p0) - (v1-v0)(p2-p0)) / det, NOT normalised. w = +1 if det >= 0 else -1. det == 0 is not skipped: t = rotated (n0+n1+n2)/3, w = +1. Per-vertex accumulate, then Gram-Schmidt and normalise. | CONFIRMED | We use Mikktspace-style accumulation with a bitangent-sign w. Close in direction, differs in weighting, degenerate-UV handling and w. | DONE: `generateTangents` is now the game algorithm incl. clones; oracle mean 0.9966 worst, 1.0000 on core fixtures |
| 10 | Tangent vertex split | If a later triangle's w differs from the vertex's stored w, a new vertex is appended and the index rewritten. UV sets, color, dangly constraints and skin weights are copied to the clone. AnimMesh nodes skip this and overwrite. | CONFIRMED | We never split on handedness, so there is a rare seam artifact on NormalAndSpecMapped meshes with mirrored UVs. | DONE (same change as 9) |

## Decompiler (binary.go) check against these findings

- Reads the GPU vertex arrays directly and faces as GPU indices, which matches the engine layout (finding 12). OK
- Tangents: vec3 stream plus +-1 handedness float, default +1 when absent. Matches findings 11 and 12. OK
- Colors: bytes / 255. Matches the engine's byte encoding. OK
- Face adjacency and plane distance are skipped on read. The compiler writes 0xFFFF adjacency, but game binaries carry real values (finding 15). The engine recomputes them at load, so this is probably fine.
- Smoothing group is not stored in binaries, so it decompiles to 0 and the stored normals carry the smoothing. Expected.
- Skin, dangly, controllers and animations were not examined in this pass.
